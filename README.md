# 双马团 · Double Horse

**V0.1 — 可点击的团本竞拍全流程 Demo**

体验地址：<https://2ez4jz.github.io/double-horse/>

React 19 + Vite。无需账号、无需 Supabase、无需 API Key；全部演示数据在当前浏览器中运行及保存。没有真实支付、跨设备多人同步或服务端权限保证。

## 开始体验

1. 在大厅选择黑暗深渊、剃刀沼泽或诺莫瑞根，输入游戏昵称并选择职业、定位。
2. 点击「快速匹配」，补满模拟队员。切换团长视角，点击「团长开始团本」。
3. 模拟击败 Boss，选择预设掉落或手动录入物品，点击装备旁的「开始拍卖」。
4. 模拟玩家每 4.5 秒竞价；自己可最低加价或自定义出价。想稳定中标，可关闭自动竞价。
5. 30 秒结束，也可由团长提前结束；无人出价则流拍，可重新拍卖或取消。
6. 中标后打开模拟付款，选择 EMT、PayPal 或二维码。二维码是不可支付的示意图。
7. 「已模拟付款」仅提交声明。独立模拟到账事件在约 3.5 秒后确认；可关闭自动核验，由团长确认或拒绝。
8. 核验通过后分配装备。处理完当前 Boss 掉落再前进，完成 3 个 Boss。
9. 在收益结算页登记测试收款账户、调整佣金与补贴，核对账目后锁定结算。
10. 单笔模拟付款可选择发送、失败、待审核。批量发送仅处理 pending 项，已发送项不重复发送。
11. 在报告页查看全团收益、交易明细、完整日志并导出 JSON。顶部重置按钮可重新开始。

团长与玩家是同一浏览器中的演示视角；不是认证权限。其他成员由本地模拟器扮演。所有账户强制生成 `@example.test` 虚构邮箱，请勿填写真实支付资料。

## 示例数据

参考用户提供的[魔兽无限副本攻略](https://www.wx-wow.com/dungeons.html?v=278)，每个副本摘选 3 个 Boss、每个 Boss 2 件物品，共 9 个 Boss、18 件示例装备。预设掉落显示名称、图标和部分属性；保留攻略中的中文叫法。这里只演示流程，不提供完整攻略或完整掉落表。

团队人数为 **10 / 20 / 40 人演示扩编**，不代表游戏正式副本人数；所有竞价、CAD 金额和补贴均为虚拟测试设置。游戏素材版权属于其原权利人，本项目为非官方演示。

## 财务规则

所有金额以整数分保存。到账核验产生唯一收入流水，退款产生对应退款流水。重拍保留之前轮次及收退款历史。未付款、失败付款不计入收入。

净确认收入 = 平台佣金 + 模拟处理费 + 全体成员基础分红 + 补贴/奖金。

补贴可叠加：团长固定补贴、按职责固定补贴、指定成员固定奖金和按净确认收入比例奖金。均分尾差按成员入队顺序逐人分配 1 分。余额不足或收款账户缺失时不能锁定结算。锁定后禁止修改财务、退款及重复结算；已发送付款不能再次发送。

默认 40 人样例：收入 $5,000 → 佣金 $500 + 团长 $100 + 两位坦克 $100 + 四位治疗 $100 → 基础分红池 $4,200 → 每人 $105，补贴另计。

## 本地开发

```bash
npm ci
npm run dev
```

```bash
npm test          # 交易状态和财务测试
npm run test:ui   # 构建后执行完整 DOM 点击流程
npm run check    # 全部验证
npm run build    # 生成 dist/ 及仓库根目录 GitHub Pages 产物
```

- 源码：`app/src/`
- 交易状态机与财务逻辑：`app/src/engine.js`
- 副本样例：`app/src/data.js`
- 测试：`tests/`
- 工作日志：`docs/WORKLOG-2026-10-14.md`
- GitHub Pages：现有 main 分支根目录部署，根目录 `index.html`、`assets/` 和 `images/` 由构建脚本生成，修改源码后需重新构建并提交产物。
